Documentacion Tecnica de Arquitectura

*Andres Pagan Roncall*

Version 6.0 \| On-Premise (WSL2 Ubuntu) \| Python \| Multi-agente

**1. Descripcion General**
==========================

Sistema de automatizacion inteligente para hoteles especializado en
reservas de habitaciones. Los huespedes interactuan via WhatsApp con un
Recepcionista Bot impulsado por agentes de IA. Los pagos se procesan via
Mercado Pago con su propio container y tunel Ngrok dedicado.

  **Caracteristica**   **Detalle**
  -------------------- --------------------------------------------------
  Lenguaje             Python
  Entorno              WSL2 Ubuntu / Docker Compose
  Modelo AI            AI Model Qwen2.5-3B-Instruct (via Ollama)
  Arquitectura         Microservicios desacoplados / Multi-agente / MCP
  Mensajeria           WhatsApp
  Pagos                Mercado Pago --- Pasarela de pagos
  Tunel WhatsApp       Ngrok / Tunel-WH-Whatsapp
  Tunel Pagos          Ngrok / Tunel-WH-MercadoPago

**2. Arquitectura General --- Docker Containers**
=================================================

El sistema esta compuesto por containers independientes comunicados por
una red interna. Cada container tiene su propio archivo .env para
desacoplar credenciales.

  **Nombre en diagrama**                                                                                                               **Container**               **Responsabilidad**
  ------------------------------------------------------------------------------------------------------------------------------------ --------------------------- -------------------------------------------------------------------------------
  Ngrok / Tunel-WH-Whatsapp                                                                                                            Docker-container Ngrok      Expone el Webhook Whatsapp al internet publico
  Ngrok / Tunel-WH-MercadoPago                                                                                                         Docker-container Ngrok      Expone el Webhook Payment al internet publico
  Webhook Whatsapp + System Whatsapp-sender                                                                                            Docker-container Whatsapp   Recibe y envia mensajes WhatsApp
  Webhook Payment + System Payment                                                                                                     Docker-container Payment    Recibe notificaciones de Mercado Pago y procesa pagos
  System Core                                                                                                                          Docker-container Core       Orquesta todos los AI Agents y MCP Servers (Customer service + Admin service)
  Ollama + AI Model Qwen2.5-3B-Instruct                                                                                                Docker-container AI         Corre el modelo de lenguaje local
  DB Transaccional PostgreSQL Hotel + DB Transaccional PostgreSQL Payments + DB Cache Redis ShortMemory + DB RAG PostgreSQL PGVector   Docker-container DB         Todas las bases de datos del sistema

**3. Flujos del Sistema**
=========================

**3.1 Flujo Principal --- Mensaje Entrante del Huesped**
--------------------------------------------------------

-   1\. Recibe mensaje: El User envia un mensaje al Recepcionista Bot
    > por WhatsApp

-   2\. Reenvia mensaje: Ngrok Tunel-WH-Whatsapp reenvía el mensaje al
    > Webhook Whatsapp

-   3\. Captura mensaje: El Webhook Whatsapp captura el mensaje y lo
    > envia al System Core

-   4\. Envia mensaje: El System Core activa el area Customer service y
    > sus AI Agents

-   5\. Envia mensaje: El System Whatsapp-sender envia la respuesta al
    > Recepcionista Bot

-   6\. El Recepcionista Bot entrega la respuesta al User en WhatsApp

**3.2 Flujo de Pago --- Mercado Pago**
--------------------------------------

-   1\. AI Agent PaymentAgent genera un link de pago via MCP Server
    > McpPayments

-   2\. AI Agent WriterAgent envia el link al huesped via MCP Server
    > McpMessenger

-   3\. El huesped realiza el pago en la Pasarela de pagos de Mercado
    > Pago

-   4\. Mercado Pago notifica el pago al tunel publico Ngrok
    > Tunel-WH-MercadoPago

-   5\. El Webhook Payment recibe la notificacion

-   6\. El System Payment valida y registra la transaccion en DB
    > Transaccional PostgreSQL Payments

-   7\. El System Core confirma la reserva y notifica al huesped

**3.3 Flujo Admin --- Administrador del Hotel**
-----------------------------------------------

-   1\. El administrador del hotel envia un mensaje al bot por WhatsApp

-   2\. El mensaje llega al System Core via el mismo flujo de Webhook
    > Whatsapp

-   3\. El System Core activa el area Admin service (area dedicada
    > exclusivamente a administradores)

-   4\. AI Agent Nexus (Admin) reconoce el perfil de administrador y
    > habilita comandos de gestion

-   5\. Los AI Agents procesan la solicitud con acceso a funciones
    > administrativas

-   6\. La respuesta se envia al administrador via System
    > Whatsapp-sender

**4. System Core --- Dos Areas Dedicadas**
==========================================

El System Core contiene dos areas completamente separadas e
independientes. Cada area tiene sus propios AI Agents y MCP Servers. No
comparten instancias entre si.

  **Area**           **Dirigida a**                   **Descripcion**
  ------------------ -------------------------------- -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  Customer service   Huespedes (clientes del hotel)   Area dedicada exclusivamente a la atencion al cliente. Gestiona reservas, consultas, pagos y cualquier interaccion del huesped con el hotel.
  Admin service      Administrador/es del hotel       Area dedicada exclusivamente a la gestion administrativa. Permite a los administradores gestionar habitaciones, ver reportes, modificar precios, revisar reservas y controlar el sistema.

**5. AI Agents**
================

Cada area (Customer service y Admin service) tiene sus propios AI
Agents. Todos consumen el AI Model Qwen2.5-3B-Instruct via Ollama
(Docker-container AI).

**5.1 AI Agents --- Customer service**
--------------------------------------

  **AI Agent**              **Descripcion en diagrama**            **MCP Servers que usa**
  ------------------------- -------------------------------------- ------------------------------------------------
  AI Agent Nexus            Orquestador                            MCP Server McpRouter
  AI Agent Identifier       Identifica quien envio el mensaje      MCP Server McpWhatsapp, MCP Server McpDatabase
  AI Agent QueryAgent       Consulta la DB                         MCP Server McpDatabase
  AI Agent KnowledgeAgent   Consulta el RAG                        MCP Server McpRag
  AI Agent WriterAgent      Redacta Mensaje                        MCP Server McpMessenger
  AI Agent GuardAgent       Encargado de Seguridad                 MCP Server McpSecurity
  AI Agent PaymentAgent     Encargado de revisar y atender pagos   MCP Server McpPayments

**5.2 AI Agents --- Admin service**
-----------------------------------

  **AI Agent**              **Descripcion en diagrama**            **MCP Servers que usa**
  ------------------------- -------------------------------------- ------------------------------------------------

  AI Agent Identifier       Identifica quien envio el mensaje      MCP Server McpWhatsapp, MCP Server McpDatabase
  AI Agent QueryAgent       Consulta la DB                         MCP Server McpDatabase
  AI Agent KnowledgeAgent   Consulta el RAG                        MCP Server McpRag

**6. MCP Servers**
==================

Los MCP Servers son las capacidades de accion de los AI Agents. Cada
area (Customer service y Admin service) tiene su propia instancia de MCP
Servers.

  **MCP Server**            **Archivo**         **Capacidad**                                                                                  **AI Agents que lo usan**
  ------------------------- ------------------- ---------------------------------------------------------------------------------------------- ------------------------------------------
  MCP Server McpRouter      mcp\_router.py      Enruta mensajes entre agentes y orquesta el flujo                                              AI Agent Nexus
  MCP Server McpWhatsapp    mcp\_whatsapp.py    Consulta informacion de contacto e historial de WhatsApp                                       AI Agent Identifier
  MCP Server McpDatabase    mcp\_database.py    Lee y escribe en DB Transaccional PostgreSQL Hotel                                             AI Agent Identifier, AI Agent QueryAgent
  MCP Server McpRag         mcp\_rag.py         Busqueda semantica en DB RAG PostgreSQL PGVector                                               AI Agent KnowledgeAgent
  MCP Server McpMessenger   mcp\_messenger.py   Envia mensajes y links de pago via WhatsApp                                                    AI Agent WriterAgent
  MCP Server McpSecurity    mcp\_security.py    Valida seguridad, detecta fraude, bloquea numeros                                              AI Agent GuardAgent
  MCP Server McpPayments    mcp\_payments.py    Genera links Mercado Pago, verifica y registra pagos en DB Transaccional PostgreSQL Payments   AI Agent PaymentAgent

**12. Comandos Utiles (WSL2 Ubuntu)**
=====================================

**12.1 Primera vez**
--------------------

-   Posicionarse en la raiz del proyecto: sistema\_reservas\_hotelero/

-   Levantar todos los containers: docker compose up -d

-   Descargar AI Model Qwen2.5-3B-Instruct (solo una vez,
    > aproximadamente 2GB): docker exec -it docker\_container\_ai ollama
    > pull qwen2.5:3b

**12.2 Uso diario**
-------------------

-   Levantar: docker compose up -d

-   Detener: docker compose down

-   Ver logs del System Core: docker compose logs -f core

-   Ver logs del System Payment: docker compose logs -f payment

-   Ver URL del Tunel-WH-Whatsapp: curl
    > http://localhost:4040/api/tunnels

-   Ver URL del Tunel-WH-MercadoPago: curl
    > http://localhost:4041/api/tunnels

**12.3 Verificacion de salud**
------------------------------

-   Estado de todos los containers: docker compose ps

-   Verificar Ollama: curl http://localhost:11434/api/tags

-   Verificar Webhook Whatsapp: curl http://localhost:8000/health

-   Verificar Webhook Payment: curl http://localhost:8002/health

-   Verificar System Core: curl http://localhost:8080/health

**13. Seguridad y Buenas Practicas**
====================================

-   Nunca subir ningun .env a Git. Agregar \*\*/.env al .gitignore

-   Ngrok Tunel-WH-Whatsapp expone solo el puerto 8000 (Webhook
    > Whatsapp)

-   Ngrok Tunel-WH-MercadoPago expone solo el puerto 8002 (Webhook
    > Payment)

-   DB Cache Redis ShortMemory requiere password obligatorio

-   Cada DB PostgreSQL usa su propio usuario independiente sin
    > privilegios de superusuario

-   AI Agent GuardAgent valida cada mensaje entrante antes de que llegue
    > a AI Agent Nexus

-   Mercado Pago en modo sandbox durante desarrollo (MP\_SANDBOX=true)

-   La red interna de Docker solo expone al host los puertos
    > explicitamente mapeados

-   WA\_VERIFY\_TOKEN valida que los webhooks provienen de Meta

-   MP\_WEBHOOK\_SECRET valida la firma HMAC de las notificaciones de
    > Mercado Pago
